Three rules that come before the style

These apply to all three, on every client site.

Phones first

99%

of our clients' visitors arrive on a phone. Build at 360px and let the layout grow outwards — never design at desktop width and squeeze it down.

  • 44×44px tap targets on touch, 8px apart
  • 16px minimum on form inputs, or iOS zooms the page
  • Nothing hover-only; tel: links on every phone number
  • No horizontal scroll at 360px — verify it, don't assume it

SEO, as you build

Local

search is the whole game for a small business. SEO is not a phase at the end — most of it is decided by how the page is built.

  • Unique title, description and canonical on every page
  • LocalBusiness + FAQPage structured data
  • LCP under 2.5s, CLS under 0.1 on a mid-range phone
  • Footer NAP matching Google Business Profile exactly

Full SEO checklist →

Readable and obvious

65ch

measure, 16px body text, one primary action per screen. Clean and intuitive beats clever every time.

  • Line height 1.5–1.65, left-aligned, short paragraphs
  • Plain language — no "leverage", "bespoke", "seamless"
  • Say what happens next, not "Submit"
  • Fewer choices. Cutting the nav is usually the biggest win

The test: hand the phone to someone who has never seen the site and say nothing. If they ask “what do I press?”, the page has failed.

Before you build anything

Stop at the first rung that works.

  1. 01 Does it need to exist? Half the sections in a brief don't. Say so once and move on.
  2. 02 Is it in this repo already? Copy the pattern from the matching demo page rather than starting a new one.
  3. 03 Does the platform do it? <dialog>, popover, <details>, input type=date, scroll-driven animations, view transitions.
  4. 04 Is there a known-good library? Toasts, drawers, command menus and date pickers are solved. See the library list.
  5. 05 Only then, write it And only the minimum that works.

Non-negotiable in all three styles

Not style choices. These don't get traded away for a deadline.

  • Visible :focus-visible ring on everything interactive
  • Body text at 4.5:1 contrast, large text at 3:1
  • prefers-reduced-motion honoured
  • Fully operable by keyboard
  • Real text, never copy baked into an image
  • One h1, headings in order, landmarks present
  • Width and height on images to stop layout shift
  • Fluid with clamp(), built at 360px first
  • 44×44px tap targets on touch, 8px apart
  • 16px minimum body text and form inputs
  • Unique title, description and canonical per page
  • LCP under 2.5s, CLS under 0.1 on a mid-range phone
